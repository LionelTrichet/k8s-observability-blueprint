# Security

## Threat Model

This repository runs a disposable observability environment on a developer workstation or a CI runner. The assets are the host, the local Docker daemon and the synthetic telemetry inside the cluster.

In scope:

- accidental exposure of cluster services beyond the host;
- workload privilege beyond what the demo needs;
- credentials committed to the repository;
- untrusted inputs affecting failure behavior or metric cardinality;
- CI permissions and secret use.

Out of scope: multi-tenant clusters, hostile cluster administrators, production data and Internet-facing deployment.

## Local Development Scope

The environment is meant to be created, validated and deleted. It is not hardened for long-lived operation or shared use.

## Cluster Exposure

- Every Service created by this repository is `ClusterIP`.
- No NodePort, LoadBalancer, Ingress or hostPort is created.
- kind exposes the Kubernetes API on the local host only, which is its default.

`make verify` checks the Service types, host ports and Ingress objects in both namespaces.

## Demo Failure Endpoints

The demo workload intentionally exposes a crash endpoint for local failure validation. Do not deploy this workload as an Internet-facing application.

`/error`, `/slow` and `/crash` have fixed behavior. No request parameter changes a delay, an exit code or a failure mode, so the endpoints cannot be turned into an unbounded resource sink.

## Container Security

The demo pod runs with:

- `runAsNonRoot: true` on a distroless `nonroot` image;
- `readOnlyRootFilesystem: true`;
- `allowPrivilegeEscalation: false`;
- `capabilities.drop: [ALL]`;
- `seccompProfile: RuntimeDefault`;
- CPU and memory requests and limits.

The binary is statically linked with `CGO_ENABLED=0`.

## Service Account Boundary

- The demo workload does not call the Kubernetes API. Its ServiceAccount and pod set `automountServiceAccountToken: false`; there is no Role or RoleBinding.
- The Collector does not call the Kubernetes API. Its ServiceAccount has no mounted token and no ClusterRole.

## Port Forwarding

All port forwards bind `127.0.0.1`: demo 18080, Prometheus 19090, Grafana 13000, Tempo 13200. They are started per script and stopped on exit.

## Telemetry Data

All telemetry is synthetic. Metric labels are limited to fixed route names and HTTP status codes; nothing is derived from user input, trace IDs or pod identity. Traces contain fixed attributes only.

## No Runtime Secrets

The repository contains no Grafana password, API token, TLS key, registry credential or cloud credential. The Grafana admin password is generated by the chart at install time and read from the cluster Secret on demand.

## Third-Party Images and Charts

The environment pulls public images and Helm charts:

- `kindest/node`, pinned by digest;
- kube-prometheus-stack, OpenTelemetry Collector and Tempo charts, pinned by exact chart version; their images follow the pinned chart versions;
- `golang` and `gcr.io/distroless/static-debian13` base images for the demo.

CI verifies the checksums of kind, kubectl and Helm before installing them.

## CI Permissions

- `permissions: contents: read`.
- `actions/checkout` runs with `persist-credentials: false`.
- Triggers are `push` and `pull_request`; `pull_request_target` is not used.
- No repository secrets, registry logins, cloud accounts or self-hosted runners.

## Known Limitations

- Chart-managed images are pinned through chart versions, not by digest.
- In-cluster traffic, including OTLP export, is plaintext. It never leaves the kind cluster.
- The kind cluster runs with the privileges kind requires from Docker on the host.
- Grafana uses its local admin account.

## Vulnerability Reporting

Please report security issues privately through GitHub's **Report a vulnerability** option on this repository instead of opening a public issue. Include the affected file or component and steps to reproduce.
